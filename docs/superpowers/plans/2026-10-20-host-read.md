# Host read Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** add `sql-auditor host`, a Windows-only command that reads the SQL Server host from an elevated prompt (event logs, VSS, SQL Writer's log, filter drivers, power plan, failover cluster, Azure extension logs, Agent job output files) and writes one zip.

**Architecture:** a new package `host/` holds everything. Every rule the spec states (window, tokens, event source, XPath, XML parsing, JSON shapes, file selection, manifest, exit codes) is a plain function tested on the Linux CI. The Windows calls sit in `*_windows.go` files behind a `Sources` struct of functions, so the orchestrator `host.Run` is tested on Linux with fakes. `cmd/sql-auditor/main.go` only dispatches.

**Tech Stack:** Go 1.26, standard library (`syscall`, `archive/zip`, `encoding/xml`, `encoding/json`, `regexp`), `github.com/microsoft/go-mssqldb` (already direct). No new module.

**Spec:** `docs/host-read-spec.md` (commit of this plan). Read it whole before any task; section names below refer to it.

## Global Constraints

- No new module in `go.mod`; `golang.org/x/sys` stays `// indirect` (`tui/screen/terminal_windows.go` explains why). Windows calls use `syscall`.
- Every DLL other than `kernel32.dll` is loaded by absolute path in the system directory returned by `GetSystemDirectoryW` (helper `systemDLL`, Task 10).
- PowerShell only as `<systemdir>\WindowsPowerShell\v1.0\powershell.exe -NoProfile -NonInteractive -Command <script>`; never `-EncodedCommand`. Scripts are Go string constants.
- Windows-only code lives in files suffixed `_windows.go`; their non-Windows twins (`_other.go`, `//go:build !windows`) return `ErrNotWindows`.
- Default window: 90 days before today, local midnight. `--since yyyy-mm-dd` in local time.
- Caps: 20,000 events for query 1 per log, for query 2 and for query 4; none for query 3; 50 MiB of extension logs; five job output files per step, each its last 1 MiB; message cut at 2,000 characters.
- Archive: `<instance>-<yyyy-mm-dd>-<hhmmss>.host.zip`, created `O_EXCL`, one top-level directory of the same name without `.zip`, removed on a zip error or interrupt.
- Exit codes: 0 archive written, every source read, absent or refused; 2 archive written with a failed source, an unanswered instance or a machine mismatch, or no archive (refusal, zip error, interrupt); 1 never.
- stdout: one line per source, then the archive path as the last line, only when an archive was written. Everything else on stderr.
- `CLAUDE.md`: no client identifier in code, fixtures, comments, commit messages; commit messages in English; `go test ./...` passes before each commit; no attribution trailer in commits.
- `gofmt`, `go vet ./...`, and for every task touching Windows files `GOOS=windows go vet ./...` and `GOOS=windows go build ./cmd/sql-auditor` must pass.

## Review Focus

1. `--to` names a directory that does not exist or is not writable: refused with exit 2 before any source is read, no archive (test in Task 9).
2. A job output file of several hundred MiB: only its last 1 MiB is read, by seeking, never `io.ReadAll` (test in Task 7 with a 3 MiB file and a reader that fails if read before the offset).
3. `--since` on a machine whose zone is not UTC: the XPath bound is the UTC instant of local midnight (test in Task 4 with `time.FixedZone("x", -7*3600)`).
4. One source panics or returns an error: the others are still read, the manifest names the failure, exit 2 (test in Task 9).
5. A job name holding `[`, `*`, `?` or `.`: the file match is literal for those characters (test in Task 2).
